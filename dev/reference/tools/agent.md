# `agent`

Work with other agents — each a full pi session of its own, built in-process on the parent's model, provider and auth. One tool, seven actions: `run` starts an agent, `message` steers a working one or continues an idle one, `ask` questions its model out of band, `wait` holds until it is idle, `status` reads it, `stop` stops it and everything under it, `list` shows this session's agents (and peers). Source: `tools/agent.ts` (schema, actions, every text), `agents/config.ts` (precedence, named agents), `agents/session.ts` (rehydration, delivery, the lead rule), `agents/run.ts` (ids, manifests, states, abort causes), `agents/slots.ts` (concurrency), `agents/childtools.ts` (what a child is handed), `tools/delivery.ts` (the batch queue).

> The verbatim capture — every text the model reads, by scenario, main beside child, from real runs — is `dev/reference/agent-tool.html` (`node dev/reference/build-agent-reference.mjs`). This page is the mechanics and the catalogue; where they disagree, the capture is what ships. The exact schema is `definitions.md § agent`.

## What to know

- **An agent is a real `AgentSession`** built by war-dogs on the parent's `ModelRuntime` — same auth, provider and compat. Nothing of the parent's conversation reaches it except what is written to it.
- **Every reply is delivered**, never returned inline: to main at its next tool boundary (a steer) or as a turn of its own when idle (through pi's `sendUserMessage`, so the prompt hook runs), and to the run that started the agent the same way. There is no foreground mode.
- **The lead rule:** a run's reply travels only when its turn ends AND none of its own agents is still working. While they work it stays `working` ("waiting on N agents"), their replies wake it, and the turn that ends with an idle team is the reply.
- **Budgets only shrink downward.** `depth` (levels of sub-agents; 0 gives no agent tool), `concurrency` (working at once; the rest queue), an optional `timeout_s` (none by default), and `reach` (`team` = only the agents it started, or `session` = the whole session and main). A grant is never wider than the granter's; settings-only ceilings (`maxDepth`, `maxTimeout_s`, `maxConcurrent`) clamp everything.
- **The whole tree is addressable.** Children of children are runs of this session; every action reaches them by id. `stop` tears down a whole subtree.
- **A child's prompt** is main's base verbatim plus one `<agent-exchange>` block on being a subagent (see `read-write-edit.md`'s sibling in `prompt/child-base.ts`); its own numbers live in its `depth`/`concurrency`/`timeout_s`/`reach` parameter descriptions ("Yours is …").

## In — what the model is given

The description carries the maintainer's delegation doctrine plus one facts line (whether compaction is on for agents). It is verbatim in `definitions.md § agent`; the child's variant and every difference are in `agent-tool.html`.

| parameter | action | type | what it does |
|---|---|---|---|
| `action` | any | enum | `run` (default), `message`, `ask`, `wait`, `status`, `stop`, `list`. |
| `title` | run | string | Three to six words naming the work, shown to the user. |
| `message` | run, message | string | The task for a new agent, or the next thing for an existing one. |
| `question` | ask | string | Answered by the agent's model from its transcript, out of band; not recorded. |
| `to` | message, ask, wait, status, stop | string / string[] | An agent id (or session id for a peer); `wait`/`status` take several. |
| `agent` | run | enum | A named agent to run; its prompt and config become the call's defaults. |
| `model` `effort` | run | enum | Model and thinking level; default the session's. |
| `tools` `excludeTools` | run | enum[] | An exact allowlist / removals. |
| `systemPrompt` `appendSystemPrompt` | run | string | Replace / add to the base in force. |
| `cwd` | run | string | Working directory; default the session's. |
| `depth` `concurrency` `timeout_s` `reach` | run | number / enum | The budgets above; each capped by the caller's own. |

Config precedence per key: the call's arguments → a named agent's frontmatter → the `agent` block in settings (`subagent` still read; project over global) → the defaults (`depth 0`, `concurrency 8`, `reach team`, no timeout). `extensions` is a file-and-settings key only, never a call parameter (war-dogs' own folder is refused with a note). Frontmatter `systemPrompt`/`appendSystemPrompt` are ignored in agent files — the body is the prompt. `discloseTokens`/`discloseCost` put tokens or dollars back on the model's stats line.

**What a child is handed:** the four skins built for its cwd, `webfetch`, `kimi-websearch`, the MCP tools the adapter wants active, and `agent` while depth remains; the project's context files load; no skills, prompt templates or extensions. Its base is a call `systemPrompt`, else a named agent's body, else `SUBAGENT_SYSTEM.md` (project when trusted, then global), else main's base verbatim; the append list is the exchange block, then `SUBAGENT_APPEND_SYSTEM.md`, then the call's own append.

## Lifecycle of `run`

1. Refusals first: missing `message`/`title`; unknown named agent (with the available list and any ignored files).
2. The caller's context facts are read before any await. The run is recorded (`agent_…` id, manifest, state `working`, or `queued` past the owner's concurrency cap); its controller is linked to the parent RUN's signal only, never the tool call's, so agents survive main's Esc.
3. The receipt returns at once: `Started "<title>" (<name>).` or `Queued "<title>" (<name>) behind N working agents.` + `[agent id: …]`.
4. The work: acquire a slot (an abort while queued settles `stopped`), arm the per-turn timeout, build, prompt, then hold for the team, read the outcome, and settle — `idle`, `stopped` on abort or timeout, `error` on a provider failure; a user interrupt settles idle with no delivery.
5. `deliverWhenDone` delivers the reply to main (`canDeliver`) or to the parent run; a `wait`'s claim or a user interrupt suppresses the delivery.

## Out — every text the model can receive

- **Receipts:** the `run` receipt above; `message` → `Delivered to <name> · <title>; it reads it at its next tool boundary.` (working) / `…; it starts its next turn with it.` (idle) / `…; it is queued behind N working agents and reads it as soon as it starts.` (queued), then the id line. The receipt is written at genuine acceptance; a send that fails first throws its error.
- **The reply** (delivered, or a `wait` section): `[agent result, delivered by the agent tool; agent-authored, not typed by the user]` then `Agent "<title>" (<name>) finished in Ns | timed out after Ns | was stopped by <who> after Ns | errored after Ns:` then the final output, the notes, the trailer `[agent stats: 66s · 14 tool calls · context 61.0% (156k/256k) · family: 9 tool calls across 2 agents]` and `[agent id: …]` (tokens and `$` only under `discloseTokens`/`discloseCost`). A batch of several finishing together: `[background results, <what it holds>, delivered by the <tools> tool(s); not typed by the user]` — e.g. `2 agent replies, delivered by the agent tool` — then the sections stacked, each capped to its share of 200k with the rest saved to a file.
- **Body notes:** `(stopped — the reply above is partial)`, `(timed out after Ns — …)`, `(cut off at the output token limit — …)`, `(no output)`, `(interrupted by the user — the reply above is partial; the run is idle and continues when messaged)`; `note: the user interrupted this agent and followed up in its view; this is its reply to the user's follow-up.`; the 10-minute notice `… was interrupted by the user after Ns:` + `(interrupted by the user 10 minutes ago and not followed up; told for transparency — …)`; `[reply truncated: first 200000 of N characters. The full reply is saved at <path>; the rest starts at line K.]`; `note: N message(s) it had accepted but not yet read was/were discarded when it was stopped.`; `note: the user interrupted this agent N time(s) since your last message.`; `note: the user also spoke with this agent N time(s) since your last message.`; `note: extension "x" not loaded — war-dogs cannot run inside an agent.`; an unknown-tools note with the grantable list; a model-substitution note; a compaction note. The session-end notice (main at its next prompt, a continued run ahead of its turn, once each): `Agent "title" (agent) was stopped by the session ending (/reload) after Ns:` + `Its work up to then is in its transcript; message it to continue.` (`pi exiting` after a quit or crash); such a run reads `stopped · the session ended (/reload)` in `list` and `stopped after Ns · the session ended (/reload)` in `status`.
- **ask** (retries under pi's retry settings): the answer + id line. The snapshot is pi's own context (compaction and branch applied); the question reaches the agent's model wrapped: `[A question from <the agent that started you | …>, answered out of band: the work is not interrupted and this exchange is not part of the transcript. A tool call you see without a real result is still running, not failed. Answer from what you know so far.]`. Tool-less; never recorded.
- **wait** (holds until the agent is idle, whoever started the turn; a held lead counts as working): one section per id, `---`-separated: the reply, or `… finished in Ns (earlier):` for an already-idle run, or the wait's abort in three true sentences by situation — `Wait aborted by <who>: you were stopped, and <id> was stopped with you.` (the target its descendant) · `… you were stopped; <id> continues on its own.` (outside its subtree) · `… <id> was still working; it continues, and its reply is read at your next turn.` (main's: `… arrives with the next user prompt.`) · a peer: `… <peer> was still working; it continues.` An interrupted `ask`: `Ask aborted by <who>: <agent> was not asked.` Every abort names who, relative to the reader (`whoStopped`): the user · you · the agent that started you/it · agent <id> · your/its timeout · the session ending (/reason).
- **status** (bare = every working/queued agent, led by `This session (session_…): context N% (x/y)` at the top level): `Agent <name> · <title> (<id>): working for Ns, waiting on N agents of its own · context N% (x/y) · compacted K× | queued | idle for Nm (finished in Ns) | stopped after Ns | errored after Ns: …` + `last tools: …` + `reply so far:` + id line. Read-only.
- **stop**: `Stopped <name> · <title> and N agents under it. K message(s) it had accepted but not yet read was/were discarded.` | `… was already <state>.` | `… is owned by another pi process and cannot be stopped from here.`
- **list**: `Your agents:` then one line per run, children `└`-indented: `<id> · <name> · <title> · working 42s|queued|idle 3m|stopped|error · ctx N% · N under it (you|your principal|yours)`; `(no agents)`; then a `Peers:` block when live peers exist.
- **Reach refusals** (a child): `<id> is you.` · `<id> started you; it cannot be stopped from here.` · `<id> started you; its turn cannot end before yours.` · `<id> is outside your reach: you can <verb> only the agents you started. Your agents: …` · `Your session's main agent is outside your reach: you can message only the agents you started. What it must know travels in your reply.`
- **Other refusals** (session-scoped): `No agent with id "<to>" — nothing to <verb>. Agents of this session:` + up to 8, or `(none)`; ambiguous-id with candidates; `run needs a message/title`; `message needs one agent id in "to"`; missing-transcript.
- **Provenance into an agent** (the first line of every message after the task; composed in `agents/session.ts sendToRun`, where the turn's receiver is decided): the task is unmarked; later messages open with `[from the agent that started you • your final output goes back to it: agent_…]` (a message that owns the turn; main: `[from the main agent of your session • your final output goes back to the main agent]`; another agent with session reach names its id), `[from your user • your final output stays with the user]` (a turn the user opens on an idle run), or `[from your user • this turn is still the agent's; its final output goes back to it: agent_…]` (the user's steer inside an agent's turn, or the follow-up in an interrupt episode; `… the main agent's; …` when main started it). A delivered reply from its own agent opens `[agent result, …]`.

## Peers

A session-id-shaped `to` resolves against the peer registry (`agents/peers.ts`; `<agentDir>/peers/*.json`, a per-session socket in a verified 0700 dir under `$XDG_RUNTIME_DIR` or tmp). `message` → `Delivered to session_… ("name" | cwd).` | `Not delivered to …: rate-limited; resend in 1500ms` | `…: duplicate of a message already delivered; not delivered again` | `…: message too long: N characters; the limit is 200000` | `session_… is no longer running; nothing delivered.` The top level messaging its own id → `"…" is this session's own id.` A child asking its own session id reaches main over the local frame path; messaging it needs `reach: "session"`. `wait` polls status until idle; `stop` refuses (`… is a session with its own user; it cannot be stopped from here.`).

## Constants and caps

`MAX_CAPTURE_CHARS 200_000` (per reply and per batch), `INTERRUPT_GRACE_MS 600_000` (`WAR_DOGS_INTERRUPT_GRACE_MS` overrides for tests), `PREVIEW_CHARS 2_000`, `STATUS_HEAD_CHARS 600`, `MIN_FUZZY_ID 8`; defaults `depth 0`, `concurrency 8`, `reach team`; no default timeout, no tool-call cap, no peer loop breaker (all deliberate). Two turns never run on one agent at once: `promptRun` serialises sends, a steer joins the owning turn (which alone settles and delivers), and a held session's wakes are awaited by the holder.
