# MCP — what war-dogs adds around pi-mcp-adapter

war-dogs bundles [pi-mcp-adapter](https://github.com/nicobailon/pi-mcp-adapter) and installs it at load against a Proxy of pi's ExtensionAPI, so the adapter runs as if it were a standalone extension. The tools the model sees — the `mcp` gateway, `mcpScript`, and one direct tool per server tool — are the adapter's, and so are all their texts. war-dogs adds nothing to what the model reads about MCP; it owns three things around it. Source: `mcp/index.ts` (the facade), `mcp/pi-mcp-adapter.d.ts` (the typed boundary), `index.ts` (`activateCustomTools`, `setChildExtraToolsSource("mcp", …)`), and the pinned dependency `node_modules/pi-mcp-adapter/`.

## What war-dogs owns

1. **The master switch.** With war-dogs off, the adapter is never installed — no MCP tools, no `/mcp` or `/mcp-auth`, no `mcp-scripting` skill, no `MCP:` status; the model's tool list and system prompt are pi's byte for byte. With war-dogs on, the tools are activated in canonical order and the adapter gets `session_start`; turning off sends it `session_shutdown` (servers stop, status clears).
2. **Children.** A subagent is handed the MCP tool definitions the adapter currently wants active (a live keyed source, `childToolDefs()`), so a child's MCP call runs on the parent's servers. The `agent` tool's `tools` enum lists every MCP name the adapter has registered, so a parent can allow or deny them for a child.
3. **Rendering.** The pager knows the adapter's tools (the toolmap), folds them as acts (`called mcp <tool> @ <server>`), highlights their JSON args as JSON, and shows a structural-error red when a result opens with `Error`/`### Error` or a top-level JSON `ok:false`/`error`/`isError` (`errorShapedResult` — visual only; the model's text is untouched).

## What the model reads (the adapter's, verbatim in its source)

- **`mcp`** — the gateway (status, search, describe, auth, and single tool calls). Its description is built by the adapter (the server list and actions); `promptSnippet: "MCP gateway — status, search, describe, auth, and single MCP tool calls"`. Parameters include `tool`, `args` (JSON string or object), `server`, `connect`, `describe`, `search`, `regex`, `includeSchemas`, `action`. Result texts (status tables, search results, `Server "<x>" not found. Use mcp({}) to see available servers.`, `Tool "<x>" not found. Server "<s>" has: …`, auth prompts, and the called tool's own content blocks) are all the adapter's.
- **`mcpScript`** — run a script against MCP tools; its `mcp-scripting` skill is offered through `resources_discover` (and so is absent when war-dogs is off, since the adapter never registers).
- **`<server>_<tool>`** — one direct tool per server tool the adapter exposes: name is the prefixed form, description and JSON-Schema parameters are the server's, results are the server's content blocks. The adapter marks thrown errors `isError`, but a server that returns an error *payload* arrives as a successful result — which is why the pager sniffs the structure for the error red.

Server configuration is the adapter's own (`.mcp.json`, `~/.config/mcp/mcp.json`, `<agentDir>/mcp.json`, `/mcp setup`; the `--mcp-config` flag; OAuth via `/mcp-auth`, stored in the system keyring). Its README is at `node_modules/pi-mcp-adapter/README.md`.

4. **The default browser** (belongs under "What war-dogs owns", stated here because it changes the server list the `mcp` description carries). With no configuration, one server is present: `playwright`, the bundled `@playwright/mcp` (pinned in `package.json`) registered at runtime through the adapter's `registerMcpServer` (`mcp/index.ts registerDefaultBrowser`) — never written to a file. The model reaches it through the gateway like any server (`mcp({ tool: "browser_navigate", server: "playwright", … })`); it is proxy-only (no direct tools, the same default a file entry has) and lazy (Chrome launches on the first call). A user's own server named `playwright` replaces it — the adapter's registration throws "already registered" and ours is skipped; `war-dogs.playwright: false` turns it off. Its texts are `@playwright/mcp`'s, verbatim.

## The facade (`mcp/index.ts`)

The adapter's factory is invoked with a Proxy over pi's ExtensionAPI that forwards everything — events, commands, flags, the active set — and records at two points: `registerTool` keeps every name and definition (for the toolmap, the child source, and the canonical active order), and `setActiveTools` notes what the adapter itself wants active (`wanted`) and passes the write through untouched. One adapter instance per factory run (`resetInstance()` clears the capture maps first). If pi-mcp-adapter is ALSO installed as a pi package, war-dogs yields — it skips the bundled copy and tells you once how to switch (`pi remove npm:pi-mcp-adapter`) — because otherwise pi would exit with `Tool "mcp" conflicts with …`.
