# dev/ — the war-dogs workshop

**Nothing here ships or runs inside war-dogs.** The running extension reads no file in `dev/`; if this whole folder vanished, war-dogs would run identically. This is the tooling, the tests, and the maintainer's memory.

One rule governs everything here: **understanding this project must never require digging through git history.** The durable memory is `internals/README.md` plus the code itself; a doc or a comment that sends you to an old commit to understand the *present* is a doc that failed. History is where you learn how something changed, never where you learn what it is — so keep the state here and in the code, current.

## Where things are

- **`internals/` — the memory. Read this first.**
  - `README.md` — the engineering book: the architecture, the invariants, and the decisions the code can't tell you. This is the one place memory lives.
  - `SYSTEM-PROMPT.md` — a system prompt that turns any capable LLM into a war-dogs expert; hand it to a model with file access to this folder.
  - `archive/` — dated snapshots of retired docs (the pre-restructure README and GUIDE), kept as a deliberate reference so the earlier shape is one file away, not a commit-log excavation.

- **`ci.sh` — the one verification gate.** `./dev/ci.sh` runs everything; `./dev/ci.sh quick` is typecheck + format + a headless boot. Run it before any commit that touches behaviour.

- **`instruments/` — what `ci.sh` drives, and what you reach for by hand:**
  - `acceptance-test.sh` — off = stock (screen and palette), boot-on smoke, the external-editor leg
  - `inject-test.sh` — the injected-messages feature and the project-trust gate, on the wire
  - `undo-test.sh` — Esc takes an accidental prompt back
  - `mock-llm.mjs` — a local streaming mock model with scripted tool calls
  - `agent-harness.mjs` — drives the `agent` tool in-process with exact timing
  - `agent-scenarios.mjs` — the scenarios `agent-harness` runs (one exported function each)
  - `replay-request.mjs` — replays a recorded request offline

- **`reference/` — "what the model reads", for a power user studying the context engineering:**
  - `tools/` — one page per tool, plus `definitions.md` (GENERATED by `dump-definitions.mjs`)
  - `agent-tool.html` + `build-agent-reference.mjs` — the `agent` tool's verbatim reference, every text by scenario, captured from real runs (GENERATED)

- **`generators/` — asset tooling, run rarely:**
  - `banner/` — the mascot and WAR DOGS word art (emits `visual/hud/banner.ts`'s template)
  - `gallery/` — the theme colour catalogue

- **`in-progress/` — unfinished work, and where the next session starts:**
  - `HANDOFF.md` — what is done, what is open, how to pick up.

## The discipline

- **State, not history.** When something is built, its truth goes to the code, and what the code can't express goes to `internals/README.md`. Unfinished work lives in `in-progress/`. History and scaffolding leave the tree.
- **Generated files** (`reference/tools/definitions.md`, `reference/agent-tool.html`) are regenerated from the code — never hand-edited. If one can go stale, regenerate before trusting it.
- **Keep it tidy as you go.** A file that no longer earns its place is removed the moment its state is safe elsewhere, so nobody opens `dev/` again and wonders what any of it is.
